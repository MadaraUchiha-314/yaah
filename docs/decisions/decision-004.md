# Decision 004: VitePress on bun for the documentation site, rooted at `docs/`

- **Status:** accepted
- **Date:** 2026-09-13
- **Deciders:** @MadaraUchiha-314 (approver, product-manager)
- **Work item:** [issue #3](https://github.com/MadaraUchiha-314/yaah/issues/3)

## Context

Issue #3 asks for a VitePress site, deployed to GitHub Pages, with everything in markdown,
modelled on [vite.dev](https://vite.dev/config/) and
[the-loop's site](https://madarauchiha-314.github.io/the-loop/). The generator was
therefore decided; three things underneath it were not.

**Where the site's root sits.** `docs/` already held the-loop's artifacts — specs,
capabilities, decisions, learnings, architecture — written before any site existed.

**Which JavaScript package manager runs it.** The repository carried no JS signal at all,
so detection had nothing to read.

**How the site survives contact with the loop's own documents.** Those documents are
written for GitHub's markdown renderer and are full of angle-bracket placeholders
(`<id>`, `<phase>`) and, in a repository about CI, GitHub Actions expressions. VitePress
compiles markdown as a Vue template, which is far stricter than GitHub's renderer.

## Decision

**`srcDir` is `docs/` itself**, so the loop's artifacts *are* pages. The specs sidebar is
generated by reading `docs/specs/*/` at build time and ordering the groups by issue number,
so a new work item appears without anyone editing the nav.

**bun**, per the-loop's JS/TS fallback where no signal exists, with a committed
`docs/bun.lock`. It is confined to `docs/` — a tool directory, not a second published
artifact.

**Two guards for the renderer mismatch**, plus one plugin:

- `markdown.html: false` makes markdown-it escape bare `<id>` to literal text, exactly as
  GitHub shows it.
- An expression like the release workflow's re-entry guard goes in a **fenced code block**,
  which VitePress marks `v-pre`. A repository-wide Vue delimiter override was tried first
  and rejected: the delimiters are compiler-wide, so it also broke the default theme's own
  components — the site built successfully and rendered its chrome as literal
  `{ { site.title } }` text.
- `vitepress-plugin-mermaid`, because these documents lean on *draw it rather than describe
  it* and a design whose diagrams render as source is a design nobody reads.

**And a build wrapper.** `vitepress build` exits 0 when server-side rendering throws for a
page: it logs the error, falls back to client rendering, and reports success.
`docs/scripts/build.mjs` reads that output and turns a logged error back into a non-zero
exit, which is what makes CI's `docs` job a gate rather than a formality.

## Consequences

**Easier.** One documentation tree, one build, one deploy. A decision record is a URL.
Every markdown file is linted by the same `make lint` as the code.

**Harder.** Node and bun are now prerequisites for a full local check. The mermaid plugin
adds roughly 120 packages to `docs/node_modules` and takes the site build from ~4s to ~30s
— paid in CI and on a docs contributor's machine, not by anyone installing `yaah`.

**A constraint contributors inherit.** Prose cannot contain a bare Vue interpolation; it
goes in a fenced block. The failure is loud rather than silent, which is the point of the
wrapper.

**`ignoreDeadLinks` is on**, because several checked-in documents link to repository paths
outside `docs/` (`AGENTS.md`, `.the-loop/harness-config.yaml`). Those links are correct
where those documents are read. The cost is that a genuinely broken internal link will not
fail the build.

## Alternatives considered

- **A separate `site/` directory with copied content** — two copies of every document, and
  one of them always stale.
- **MkDocs Material / Docusaurus** — fine generators; VitePress was specified, and it is
  what the reference sites use.
- **npm or pnpm for the docs** — no signal pointed at either; the-loop's fallback names bun.
- **Rendering mermaid as plain code fences** (what the-loop's own site does) — cheaper, but
  it makes every architecture diagram in the specs unreadable at exactly the moment someone
  is trying to understand the system.
