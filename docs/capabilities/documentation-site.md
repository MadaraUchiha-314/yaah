# Capability: Documentation site

> Every markdown document in the repository, published as a searchable site at
> <https://madarauchiha-314.github.io/yaah/>. This doc is the single source of truth for
> the capability's **current** behaviour.

## What it is

`docs/` is both the documentation tree and the site's source root. The guide, the
architecture index, the capability docs, the decision log, the learnings and every
checked-in spec are pages — there is no second copy and no export step. Its readers are
anyone who wants to understand yaah without cloning it, and reviewers following a link
from a pull request to the decision that explains a diff.

## Current behaviour

- All project documentation SHALL live under `docs/` and SHALL be authored in markdown.
  The only markdown outside it is the repository's entry points (`README.md`, `AGENTS.md`,
  `CLAUDE.md`), and an integration test SHALL enforce that.
- The site SHALL be generated by VitePress with `srcDir` = `docs/` and `base` = `/yaah/`.
- WHEN a spec directory is added under `docs/specs/` THEN its sidebar group SHALL appear
  without an edit to the navigation config.
- The system SHALL render ```mermaid fences as diagrams.
- WHEN VitePress logs a rendering error THEN the build SHALL exit non-zero, even though
  VitePress itself exits 0.
- WHEN a pull request changes the site's sources THEN CI SHALL build the site, so a broken
  site fails the pull request rather than the deployment.
- WHEN a push lands on `main` under `docs/` THEN the system SHALL build and deploy to
  GitHub Pages, from a workflow whose Pages privileges CI does not hold.
- The site SHALL provide local search, a per-section sidebar, and an "edit this page" link
  to the file on GitHub.

## Known constraints

- **Prose must not contain a bare Vue interpolation.** VitePress compiles markdown as a
  Vue template, so a GitHub Actions expression goes in a fenced code block. Getting this
  wrong fails the build loudly.
- **`ignoreDeadLinks` is on**, because several documents link to repository paths outside
  `docs/`. A genuinely broken internal link will not fail the build.
